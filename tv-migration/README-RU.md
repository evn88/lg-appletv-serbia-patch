# Ограниченный сценарий миграции существующей установки

Это собственный защитный сценарий постоянной замены двух JS через уже существующий writable overlay Apple TV17.0.3. Он не меняет data.img, прошивку, подписи, DRM или настройки автообновлений Store.

Сценарий предназначен для перехода с ранее проверенной локальной установки `appletv17-v3`: требуются её worker с точным SHA, исходные файлы, кандидаты и две собственные jailed bind-подмены. Подготовка откажет на другой установке или неизвестной версии. Это не универсальный установщик для произвольного телевизора.

Интерфейс: `--prepare` создаёт свежий приватный бэкап и квитанцию. До закрытия приложения требуется сохранить весь новый каталог на Mac и сверить каждый SHA, затем отдельно сохранить старый `appletv17-v3/last-status` и его атрибуты: этот служебный файл изменяет worker при снятии bind. Только после проверки бэкапов создаётся `mac-verified` с SHA квитанции. `--apply TOKEN` требует уже штатно остановленное AppleTV и меняет только два hostJS; `--verify TOKEN` проверяет постоянную пару; `--rollback TOKEN` восстанавливает исходные байты, включая после reboot, если версия и контекст совместимы. Точный порядок нужен для изучения исходников; автоматического запуска из этой папки нет.

Откат использует проверенные временные файлы и rename поверх цели. Удалять канонические merged main.js/app.js для отката нельзя: overlay может скрыть нижний файл whiteout. При обновившейся nativeверсии или неизвестных байтах сценарий откажет, чтобы не затереть новые файлы старыми.

Storeавтообновления остаются включены по выбору владельца. Гонка с обновлением ограничивается проверками версии/образа перед записью; атомарной блокировки относительно LGStore нет. Успешное применение на одном устройстве не доказывает совместимость остальных версий.

Локальные синтетические проверки shellфункций на macOS: `python3 test_transaction_macos.py`. Проверки подставляют собственные /proc, владельцев и workerзаглушки, используют временные файлы; телевизор не требуется. Они проверяют rename/rollback на локальной файловой системе и не заменяют проверку реального overlay.
